# Open Anti-Fraud

Open Anti-Fraud is an open-source backend and web component for remote biometric identity verification. It supports browser-based capture workflows, facial-image processing, liveness-oriented motion checks, face matching, and retention of verification artifacts.

> **Security notice:** biometric data is highly sensitive. This project is a software component, not a complete compliance program. Before any production use, perform a security review, configure transport security and access controls, establish retention policies, and verify the legal requirements that apply to your jurisdiction.

## Scope

The project is intended for 1:1 verification workflows. It does not provide face-database administration or 1:N identification.

Core capabilities include:

- Browser-based biometric capture through a TypeScript web component.
- Video and frame processing with configurable liveness and quality integrations.
- Motion challenges and reference-image verification flows.
- PostgreSQL metadata storage and S3-compatible object storage.
- REST and WebSocket endpoints for creating and processing verification attempts.
- Background retention of stored verification content.

## Repository layout

- `src/` — Python/FastAPI service, database migrations, processing pipeline, and container definition.
- `frontend/package/` — reusable browser onboarding component.
- `frontend/demos/open_anti_fraud_react/` — React integration example.
- `docker-compose.yml` — local development stack with PostgreSQL and MinIO.

## Prerequisites

- Docker Engine with Docker Compose.
- Node.js 20 or later and npm, if you build or test the frontend package locally.

## Local setup

1. Create your local configuration:

   ```sh
   cp .env.example .env
   ```

2. Replace every `CHANGE_ME` value in `.env` with a unique, high-entropy secret. Keep `.env` private; it is intentionally excluded from Git.

3. Start the local dependencies and the backend:

   ```sh
   docker compose up --build
   ```

   The service is exposed on port `8090`; MinIO's console is exposed on port `9001`.

The included Compose configuration is for local development only. Set `DEBUG=0`, use a reverse proxy with TLS, restrict CORS, and use a managed secrets solution before deploying to a shared or production environment.

## Frontend package

The React demo consumes a locally built archive of the onboarding package. Build and pack the package before installing the demo dependencies:

```sh
cd frontend/package
npm install
npm run pack
npm test
```

`npm run pack` builds the distributable files. The demo requires both local archives: `tdvc-face-onboarding-0.0.1.tgz` and `tdvc-0.0.1.tgz`.

Copy both archives into the demo directory, then install and run the demo:

```sh
cp tdvc-face-onboarding-0.0.1.tgz ../demos/open_anti_fraud_react/
cp tdvc-0.0.1.tgz ../demos/open_anti_fraud_react/
cd ../demos/open_anti_fraud_react
npm install
npm run dev
```

When the package version changes, use the archive name generated by `npm pack` and update the demo's local-file dependency to match it. The React demo is an integration reference, not a production deployment.

## Configuration

`.env.example` documents the minimum local configuration. Important groups are:

- Authentication: `TOKEN`, `SERVICE_KEY`, and the `*_AUTH_PROVIDER` settings.
- Browser access: `CORS_ORIGINS`, a comma-separated allowlist of trusted origins.
- PostgreSQL: `DB_HOST`, `DB_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, and `POSTGRES_PASSWORD`.
- S3-compatible storage: `S3_HOST`, `S3_PORT`, `S3_ACCESS_KEY`, and `S3_SECRET_KEY`.
- Processing: `DECODING_ENABLED`, `DECODING_PROCESS_COUNT`, and retention settings.

Do not use the development authentication mode or example configuration in production.

## Security and responsible use

- Do not commit credentials, tokens, private keys, database dumps, or captured biometric artifacts.
- Use short-lived credentials and rotate them if they are exposed.
- Protect all network traffic with TLS and limit API access to trusted clients.
- Obtain valid consent and define deletion and retention procedures before collecting biometric data.
- Review third-party model and dependency licenses before distribution.
